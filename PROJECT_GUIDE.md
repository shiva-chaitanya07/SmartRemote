# Phone Remote: Complete Project Guide

This guide explains Phone Remote in everyday language: what it does, what you need, how to start it, how to connect your phone, and how to fix common problems.

## What is Phone Remote?

Phone Remote lets an Android phone act like a wireless keyboard, mouse touchpad, and media remote for a Windows laptop. The phone can connect through the established Wi-Fi mode or the experimental Bluetooth HID mode.

There are two connection options:

1. **Android app** — the screen and controls you use on your phone.
2. **Windows companion server (Wi-Fi mode only)** — a small program running on the laptop. It receives phone commands and sends them to Windows as keyboard, mouse, and media input. Bluetooth HID mode is designed to use Windows built-in Bluetooth support instead.

Neither mode uses a Phone Remote cloud relay. Wi-Fi mode needs a trusted shared local network and a running laptop server. Bluetooth HID mode is experimental, depends on phone support, and requires the app to remain in the foreground.

## What can it do?

- Type with a phone QWERTY keyboard, including common special and navigation keys.
- Move the laptop pointer by dragging on the touchpad area.
- Tap for a left click, use a two-finger gesture for a right click, and use two fingers to scroll.
- Send play/pause and volume controls.
- Reconnect automatically after a temporary connection drop.
- Show whether the phone is connected.

## What you need

- A Windows 10 or Windows 11 laptop.
- An Android phone.
- Both devices connected to the same trusted Wi-Fi network. Guest Wi-Fi and some corporate networks block devices from talking to each other.
- For Wi-Fi mode, the laptop needs the Phone Remote companion executable or Python 3.11+ to run the server from source. Bluetooth HID mode is designed to use Windows built-in support instead.
- To build or run the Android app from source: Flutter stable, Android SDK/platform tools, and USB debugging or an Android emulator.

## Quick start: use the Windows launcher

The launcher is the easiest option for someone who does not want to type commands. The executable is generated by the build steps below and may not be included in a source-code download.

1. On the laptop, open the project's `windows_server` folder and double-click `build_launcher.bat` if `dist\PhoneRemote.exe` is not already present. The first build needs Python 3.11+ and internet access to download the pinned build dependencies.
2. Double-click `windows_server\dist\PhoneRemote.exe`.
3. In the launcher, select **Start server**. Leave the window open.
4. If Windows Firewall asks, allow access on **Private networks only**. Do not allow access on Public networks. If you are unsure whether the current Wi-Fi is trusted/private, cancel and check Windows network settings first.
5. The launcher displays the laptop IP address, port, one-time pairing code, and SHA-256 certificate fingerprint. Use its **Copy** buttons if helpful.
6. Open Phone Remote on the Android phone. Enter the laptop IP, port, pairing code, and fingerprint exactly as shown. Carefully compare the fingerprint with the launcher before connecting.
7. Connect. The phone should show **Connected**. Try a harmless action, such as moving the pointer, before typing into an application.
8. When finished, press **Stop server** or close the launcher. Closing the launcher stops the server.

The default port is `8765`. If the launcher reports that it cannot start because the port is already in use, choose a different available port in the launcher and enter that same port in the phone app. The laptop IP can change when Wi-Fi changes; use the current address displayed by the launcher.

## Quick start: run the Windows server from source

Use this option if you are comfortable with PowerShell. Open PowerShell in the `windows_server` folder and run:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python server.py --no-tray
```

The server prints the laptop's LAN address, port, one-time pairing code, and certificate fingerprint. Enter those values in the Android app and keep the PowerShell window open. Press `Ctrl+C` to stop the server. Alternatively, double-click `run.bat` after dependencies have been installed.

Do not add `--host 0.0.0.0` for ordinary use. That option listens on every network interface and exposes the service more broadly.

## Get and run the Android app

### Run it from source

Install Flutter and Android Studio/Android SDK first. Then open PowerShell in `android_app`:

```powershell
flutter pub get
flutter run
```

Connect an Android phone with developer options and USB debugging enabled, or start an Android emulator. Flutter will list available devices if more than one is connected.

### Build an APK for a phone

For a local development build, run:

```powershell
flutter build apk --debug
```

The debug APK is normally at `android_app\build\app\outputs\flutter-apk\app-debug.apk`. Copy it to the phone and install it, or install it using Android platform tools. Android may ask you to allow installation from the file manager you use. Only install builds you created yourself or obtained from a source you trust.

This debug APK is for testing. It is not the signed release bundle to upload to Google Play. Google Play release preparation is documented separately in `PLAY_STORE_CHECKLIST.md`.

## Pairing details in plain language

- **Laptop IP address:** the laptop's local address on Wi-Fi, similar to a street address used inside the home network.
- **Port:** the numbered connection endpoint. It defaults to `8765`; the number in the phone and launcher must match.
- **Pairing code:** an eight-digit temporary secret generated each time the server starts. Give it only to the phone you want to control the laptop. It changes when you restart the server.
- **Certificate fingerprint:** a short identity check for the laptop server. Compare it with the value shown by the launcher/server before connecting. If the fingerprint changes unexpectedly, stop and verify that you are connecting to the right laptop.
- **Connected status:** confirms that the phone completed the encrypted connection and pairing process.

The app remembers the laptop IP, port, and certificate fingerprint to make later connections easier. It does not save the pairing code; enter the fresh code after restarting the server.

## Security and privacy basics

Phone Remote can type into the active laptop window and move/click its pointer. Treat it like a physical keyboard and mouse: only pair a phone you control, and do not leave the server open when you are done.

The project includes several protections:

- Encrypted TLS WebSocket communication (TLS 1.2 or newer).
- Certificate fingerprint verification in the phone app.
- A fresh eight-digit pairing code for each server start, with failed-attempt throttling.
- Only one authenticated phone can control the laptop at a time.
- Limits on message size and input values, and release of held keys/buttons when a client disconnects.
- The default server binding is limited to detected private IPv4 network addresses.

Use a trusted Wi-Fi network, allow the server through Windows Firewall only on Private networks, and do not configure router port forwarding for it. A TLS connection and these safeguards reduce risk but do not make software unhackable. The security report describes the checks performed and their limitations in `SECURITY_TEST_REPORT.md`. Automated tests are not an independent professional penetration test, and the full physical-phone-to-laptop workflow should be tested before relying on it.

## Common problems

### The phone cannot find or connect to the laptop

1. Confirm the launcher/server says **Running**.
2. Check that the phone and laptop are on the same Wi-Fi network and that the network does not isolate wireless devices.
3. Use the current laptop IP shown by the launcher; do not use an old saved IP if the laptop changed networks.
4. Check that the port in the app matches the launcher.
5. If Windows Firewall asks, allow the app on Private networks only. If the prompt was dismissed, review the Windows Defender Firewall allowed-app settings and create a narrowly scoped Private-network rule for the selected port.
6. If the port is busy, stop the other server using it or choose another port in the launcher and update the phone app to match.

### Pairing code rejected

Read the code currently displayed by the running launcher. A server restart creates a new code. Check for mistyped or copied spaces, then try again. Repeated wrong attempts may cause a temporary lockout; wait before retrying.

### Fingerprint mismatch

Do not bypass the warning or guess. Confirm the laptop address and copy the fingerprint from the launcher again. If the laptop's server identity files were removed or regenerated, the fingerprint can change; update the saved fingerprint only after verifying the server is the intended laptop.

### The app disconnects when the launcher closes

This is expected. The laptop server must stay running. Start it again and enter the new pairing code.

### Keyboard input goes to the wrong place

The server sends input to whichever Windows application is currently active. Select the intended app on the laptop before typing from the phone.

### No Android APK exists at the expected path

The APK is created only after a successful Flutter build. Run `flutter pub get` and `flutter build apk --debug` from `android_app`, then check `android_app\build\app\outputs\flutter-apk\`. A failed build will not create the APK.

## Bluetooth HID mode (experimental prototype)

The app now has an experimental Bluetooth option. On compatible Android phones, it attempts to act as a standard Bluetooth keyboard/mouse, so the laptop can receive input without the Phone Remote Windows server. Android HID availability varies by device, and this path has not yet been verified on a physical phone and Windows laptop.

1. In Phone Remote, tap the Bluetooth HID option and enable pairing. Grant Bluetooth permissions and accept the Android visibility prompt.
2. On Windows, open Settings, choose Bluetooth & devices, select Add device, then Bluetooth. Pair with the phone using the phone Bluetooth name and approve both devices prompts.
3. Return to Phone Remote, refresh paired devices, and select the laptop once. The app saves the selected laptop address locally. Keep the app open in the foreground while using it.
4. If Phone Remote is closed or leaves the foreground, Android may disconnect HID. Open Bluetooth mode again; the app will try to register HID and reconnect to the saved laptop automatically. Existing Bluetooth pairing should remain, so do not unpair both devices just to reconnect. If HID is unavailable or pairing still fails, return to Wi-Fi mode and use the Windows companion.

This mode uses Android Bluetooth HID Device profile, available from Android 9 (API 28), but actual support depends on the phone Bluetooth stack. Android may unregister the HID app when it is no longer in the foreground.
